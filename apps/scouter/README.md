# scouter

- 개발 시작: 26.01.21

## API 스키마 생성 실험

면접 메모(`interviews/memos`)의 조회·등록·삭제에 Orval이 생성한 Zod 스키마와 타입을
사용합니다. API 함수와 Query는 기존 구현을 유지합니다. 기존 수동 `schema.ts`도
보존하며, 화면에서 사용하는 타입은 아직 전환하지 않습니다.

```sh
# 저장된 명세 갱신과 생성은 별도 명령입니다.
pnpm --filter @yourssu-inhouse/scouter fetch-schema
pnpm --filter @yourssu-inhouse/scouter codegen:api
```

`orval.config.ts`에서 `면접 질문 코멘트` 태그를 선택하여
`src/apis/interviews/memos/generated/schema.gen.ts`를 생성합니다.
생성 파일은 직접 수정하지 않습니다. 생성 후 `scripts/sort-generated-types.ts`로
스키마의 의존 순서를 유지하면서 타입 선언만 마지막에 모은 뒤 Prettier로 포맷합니다.

- 조회: 질문별 메모 목록과 중첩 작성자 정보를 생성 스키마로 검증합니다.
- 등록: 생성된 요청 스키마로 본문을 검증하고, 빈 201 성공 응답은 JSON으로 읽지 않습니다.
- 삭제: 생성된 경로 파라미터 스키마로 지원자·메모 ID를 검증합니다.
- 기존 Query 키와 등록·삭제 후 목록 무효화는 유지합니다.

이 도메인에는 별도 호환 규칙을 추가하지 않았습니다. 명세의 ID 정수 제약을 적용하고,
생성된 날짜·시간 검증은 UTC와 offset이 있는 ISO 문자열을 허용합니다.
최소 실험이므로 다른 도메인의 nullable·enum·파일 전송 등까지 검증했다고 보지 않습니다.

명세의 Location 응답 헤더에 schema가 없어 전체 명세 검증은 비활성화했습니다.
생성 시 경고가 표시되며, 명세 자체를 보정하지 않습니다. 공통 모델과 경로 파라미터 스키마를 사용하고
중복 본문·응답 별칭은 생성하지 않습니다.

### API·Query 생성 범위 검토

Orval의 기본 React Query 생성기도 같은 세 API로 검토했습니다. API 함수와 일반·Suspense
조회 hook, 등록·삭제 mutation을 생성할 수 있지만 이번에는 스키마 생성만 채택합니다.

- 전체 생성에서는 스키마 외에 API·Query 코드 422줄이 생성됐습니다. 생성물의 줄 수
  자체보다 직접 관리할 전송 유틸·Query namespace 연결·요청 검증 transformer가 늘어나는
  비용을 판단 기준으로 삼았습니다.
- 요청 검증 transformer는 공통 객체 본문만 지원했고, 다른 형태의 요청으로 확장하려면
  추가 구현이 필요했습니다. 기본 생성에는 삭제 경로 ID의 정수 검증도 없었습니다.
- 폴링·알림·성공 후 입력 초기화·목록 무효화는 화면 정책이므로 수동 관리가 남습니다.
  기존 API·Query가 작은 이 도메인에서는 연결 코드 자동화의 이익이 상대적으로 작습니다.
- 생성 코드의 분량을 줄이거나 내용을 재작성하는 후처리는 도입하지 않습니다.
  가독성을 위한 타입 선언의 위치 정렬만 적용합니다.

현재 자동화 범위는 스키마·타입이며 API 함수·Query 작성은 남아 있습니다. 여러 도메인에
확대하여 공통 연결 비용을 상쇄할 수 있고 Orval 기본 사용 방식을 채택할 때 전체 생성을
다시 검토할 수 있습니다.
